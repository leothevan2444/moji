## 领域边界

影片身份来自任务持久保存的 StashBox 来源＋影片 ID。入库验证必须具有这一精确关联；番号后备识别直接使用任务的完整番号，并限定到目标来源和远程影片 ID。媒体选择改为完整目标番号匹配，不再从文件名提取任务身份；不确定的视频仍通过现有人工文件选择处理。新生成的路径和附件名称对元数据番号做安全文件名转换，既有任务路径不自动更名。

Moji 决定下载哪些文件、整理产物和路径，并编排后续工作。Stash 负责 scan、generate、identify 与媒体库元数据的校验和存储。指纹零匹配时，Moji 可以复用 Stash 原生挖掘与保存 API 提交唯一的精确番号结果；不直接操作 Stash 数据库，不生成或翻译字幕。

`SCANNING` 不等于一次扫描请求已成功；完整入库还包括生成、识别和结果验证。上游 job ID 与阶段检查点持久保存，恢复应核对已有执行结果，避免重复扫描或重复交付。

识别作业 `FINISHED` 也可能包含单片保存失败。验证记录实际缺失的文件、标题、番号、日期、片商与演员字段，不把失败统一归因为未配置来源。缺失字段错误使用稳定字段名供界面本地化；旧错误保留通用提示，详情读取实际影片字段。对当前作业时间范围内、精确文件路径的 Stash 错误日志，可补充 `STASH_STUDIO_CONFLICT`；日志不可用或已轮转时仅报告已确认的缺失字段，不猜测历史原因。

任务详情按交付路径读取影片，再按已保存的场景 ID 筛选，避免单个删除的 ID 导致 Stash 拒绝整批查询。成功空结果显示关联影片未找到，连接/查询失败仍显示暂时无法加载。主动删除影片不会触发自动重建或把任务标为完成。

## 指纹失败后的番号挖掘

识别完成但结果不完整时，先核对全部已配置来源对实际场景的指纹查询；只有全部成功且均为零结果，才经 Stash `scrapeSingleScene` 以任务番号查询。任何指纹结果或查询错误均不能作为零匹配回退。关键词查询遵循 StashBox 来源顺序，旧索引来源先解析到当前 endpoint；关键词回退只查询其中的 StashBox，非 StashBox 刮削器仍走原生识别路径。仅完整 `code` 字段与任务番号一致、去重后唯一的结果可接受，不从标题猜测、不跨未配置来源搜索。多结果仍不任意选取；配置了跳过标签时通过 Stash 添加该标记后保持阻塞。

保存通过 Stash API 执行，按来源选项覆盖默认选项，遵循字段 MERGE/OVERWRITE/IGNORE、片商/演员/标签的 createMissing、封面、已组织标记、演员性别列表与旧男性开关、单名演员及多匹配跳过标记、StashBox 身份字段策略。来源字段规则整体替换默认规则；缺省、false、空列表保持区别。按 Stash 原生语义，无法解析出任何演员/标签 ID 时即使 OVERWRITE 也保留原关联，URL OVERWRITE 的输入仅为现有 URL 子集时不删减，setOrganized=false 不清除已有标记。现代 performerGenders 通过能力查询启用，旧服务使用兼容查询；不缓存能力而漏读升级后的设置。

开启封面时保存并读取实际图片字节摘要验证；关闭或来源没有图片时保留现有封面。关联实体按 Stash 设置通过其创建 API 写入完整支持的资料与图片；恢复只按精确远程身份核对，不按名字猜测、合并或接管记录。已有 StashBox 身份的场景不接受新的自动选择。没有精确结果、多结果、关联创建失败、配置/场景变更及查询/保存错误分别显示原因。

选择、有效设置和保存前快照先通过现有 `external_commands` 记录，再执行副作用。V2 计划不含凭据，上限 32 MiB，封面解码上限 8 MiB；重启或响应丢失复用原选择，核对全部目标字段及封面，不能只凭番号/身份跳过。未完成的 V1 计划用原远程 ID 升级，先持久化再补充保存；即使必填文字已完整也必须处理已有未完成计划。Stash 地址/凭据摘要、识别设置、文件归属、保存前元数据或封面变化阻止旧计划继续保存。创建与保存属于独立 Stash API 调用，不承诺跨服务事务回滚；创建响应丢失后按远程身份核对避免重复。

重新读取并通过完整入库校验后，任务完成与命令确认在同一核心事务提交。准备与保存总预算 60 秒，来源最多 8 个、场景最多 16 个，只有明确重试才再次处理已阻塞任务。已完成任务不会因更新自动重刮。原生 v0.31.1 差分与恢复证据见 [识别设置一致性复核](../reviews/2026-11-07-stash-identify-parity.md)。

## 下载文件计划

文件分为 `MAIN/SUBTITLE/DISCARD/UNKNOWN_VIDEO`，依托可信番号识别，保留 qB 原始 index、相对路径、大小、理由、部件顺序、字幕选择和优先级应用状态。广告、样片、截图等排除；不确定视频或顺序必须等待人工选择。

qB 使用 `stopCondition=MetadataReceived`；非 magnet 也先停止添加。得到元数据后暂停，持久化选择意图并应用原始 index 的优先级，再启动所选下载。不能按排序后的 UI 下标改 qB 文件；下载完成按所选文件进度判断。

`resolveTaskFiles` 只接受服务器已有计划中的合法视频 indices，并按播放顺序提交。手动选择、字幕开关和“尚未应用”的状态在外部优先级/启停操作前持久化；失败或重启能够继续核对。

## 产物与安全发布

四个路径根必须明确配置：qB 下载根、Moji 所见下载根、Moji 库根、Stash 所见库根。路径文字相同不保证共享同一实际目录；路径映射必须验证包含关系。

| 输入 | 交付产物 | 媒体工具 |
| --- | --- | --- |
| 一份独立影片，或去重后仅一份 | `CODE/CODE.ext`，保留原扩展名与字节 | 不调用 FFmpeg/ffprobe |
| 多份兼容影片部件 | `CODE/CODE.mkv`，无重编码拼接 | FFmpeg 和 ffprobe |
| 部件不兼容、顺序未知、字幕冲突 | 阻塞等待人工处理 | 不静默转码或猜顺序 |

准备任务以 `TRANSFERRING/PENDING` 排队，最多一个任务实际处理。工具执行使用应用生命周期 context，关闭时取消并留可恢复检查点；删除任务会取消对应准备。

验证源文件大小、包含关系和 hash，去除字节完全相同的视频。工作先写到带 `.stashignore` 的私有临时目录；全部验证完成后在同文件系统 rename 发布。无关或被修改的既有目标不能覆盖或冒领。

`.moji-receipts` 在提交给 Stash 的影片目录之外保存产物 hash 和任务所有权，帮助识别已完成交付。回执是恢复范围的一部分，不能随意清理。

COPY 保留源；MOVE 先停 qB，完整发布后才删除选中的源，恢复允许部分源已经删除。自动删种还要遵守独立副本和交叉做种保护，见 [运维](operations.md)。

## 字幕和生成资源

外置字幕保留默认关闭，开关覆盖所有语言，不做语言猜测；明确属于其他番号的字幕排除。单文件交付保持原影片字节，因此其嵌入轨道不会因开关被改写。

多部件嵌入字幕遵循保留设置。支持的文本部件字幕转为 SRT 并按前置视频时长平移；整片字幕保留原格式。位图部件字幕或冲突不能假装已正确处理。

Stash 全视频 transcode 由 `ingest.generate_transcodes` 控制，默认 `false`；封面、预览、sprite 与 pHash 仍由已有生成流程安排。不要因“生成播放资源”自动开启昂贵全视频转码。

## 修改时验证

- 单文件原格式与字节保持、COPY/MOVE、回执恢复、越界路径和已修改目标拒绝。
- 原始 qB index、人工顺序、意图先落盘、所选进度、重复操作和 shutdown。
- 合并、时长、字幕偏移或兼容性变化必须跑 `make test-media`，确认 FFmpeg 与 ffprobe 存在，不能把 skip 当通过。
- Stash 阶段改变覆盖 scan/generate/identify/verify、上游失败与已完成 job 恢复；不使用真实媒体库做默认回归。
