# 资源选择引擎

状态：已采用；2026-11-23 用户明确将资源选择固定为索引器结果匹配。当前证据见[仅索引器选源复核](../reviews/2026-11-23-indexer-only-selection.md)，先前固定组模型见[历史复核](../reviews/2026-11-23-fixed-rule-groups.md)。用户指引见[资源选择说明](../../docs/resource-selection.md)。

## 模型

- 规则为稳定 ID、名称、允许为空的 conditions；条件字段只允许 TITLE/SIZE/SEEDERS，全部来自索引器。规则内固定 OR，不提供组合方式或条件级否定。字面子串或 /…/ RE2 自动识别；大小/做种用闭区间，大小界面 GiB、API/YAML 为精确 bytes 字符串。
- 组前置准入和排除固定 ANY，空列表分别表示不限/不排除，排除优先。真实层级固定 ALL，引用全部为正向 ID；首个命中决定优先级。组 fallback 布尔开关允许通过前置的其他资源排在全部真实层级后，不保存兜底层级或早停。
- 组允许 0–16 个真实层级，空条件层级可保存但不命中；0 层级配 fallback=false 不选源，true 只按前置过滤选。新组默认关闭。无组不附加用户筛选，但保留目标番号及有效资源引用约束。
- 不内置版本、字幕、画质分类或词典，不从元数据补全大小/做种。索引器未知信息不默认通过。UNKNOWN 不视为匹配，未确定的必要条件或更高层使用 INSUFFICIENT_DATA，不再表示可以获取文件解决。

## 内核与编排

`internal/resourceselection` 无 I/O，策略/parser version 7。Facts 只有索引器标题、大小、做种、站点和位置及有界证据；删除路径、种子名、检查标记、可处理性和 verified。Policy 不含检查预算。条件数量不限，总 JSON 192 KiB，库 64、组 16、单层引用 32、名称 160 bytes、表达式 512 bytes。

runtime 的 selectionRound 只聚合、匹配和排序索引器候选，不持有资源获取器、不调用下载接口。按站点顺序查询，首层匹配可早停，否则取最高合格层或显式允许的兜底。同层按正数/未知/零做种、站点/稳定位置排序。每站 100、总计 1000 候选和全轮十分钟为搜索边界，不是元数据预算。

完成选择后，仅最终选中的一个资源进入既有获取/提交校验，保留身份、重复、防错文件和提交前持久化保护。此处没有增加阶段枚举、新准备队列或按候选获取重试；单资源失败沿用现有受阻/错误处理，不回到列表逐个验证。用户明确要求新下载准备阶段留待后续设计。

## 预览与界面

GraphQL previewTorrentSelection 同步返回已有 search snapshot 的纯匹配和分页，partial 来自原搜索覆盖。保留目标影片确认、临时组、服务器资源引用投影，不接受客户端 locators。删除 inspect 输入、job/state/errorCode、poll/cancel API、后台工作闭包、URL 检查参数及所有检查次数。

Web 使用单次请求和本地结果，保留迟到响应防护；切换搜索/组/目标清理结果，分页重匹配，刷新后重新点击。任务推荐不再要求 verified，也不启动后台作业。设置仅规则库与规则组两张主卡片，当前使用组在卡片上显示/切换；库可拖动整理、规则与组可直接申请删除，所有入口共用确认弹窗并清除引用、保留空层级。条件为单行，优先层级在组窗口内为独立卡片，不增加新编辑窗口。前置两个范围互斥，后端拒绝交集。保留三个索引器字段及现有自动保存。体验验收见[资源配置体验复核](../reviews/2026-11-23-resource-selection-ux.md)。

## 持久化与交付

报告 payload v2 只记录索引器决定，不含 Fetches 或 verified；历史 v1/v2 在运行报告仍可用时均可读，不重解释旧策略，历史人工报告原样保留。文件证据来源词条只在历史显示命名空间保留，不是可配置字段。

删除 torrentsearch 元数据预览作业实现及服务调度；runtime v9 只 DROP torrent_selection_previews，旧 v8 迁移不可改写。搜索快照和任务不删除，core schema 不变。下载必需的有界 artifact cache 保留，删除其文件分析副本和旧 inspection 命名。

不自动迁移配置；按用户明确授权备份后手动移除四个 PATHS 条件、空规则与引用、无意义空层级及 per_site/max_fetches，保留索引器条件和其他配置。实际数量及运行验收以最新复核为准。

早期验收仅作历史：[首版选择器](../reviews/2026-11-21-resource-selection.md)、[规则库与组](../reviews/2026-11-21-resource-rule-groups.md)。

## 2026-11-24 报告完全归运行库

用户确认去掉独立核心“精简决定”：任务执行与恢复由已有核心资源身份、已接受来源、附件、文件计划、路径和状态/audit 负责，不增加选择摘要或报告引用。选择解释全部属于运行库现有 diagnostics（resource-selection-report），按 task_id 取最新记录。运行记录包装报告与 revision/generation/来源摘要，避免读到未来状态或前一资源的说明；不依赖核心报告指针。已有报告 payload、策略/parser、schema 版本不变，不增加迁移/兼容分支。core v10 既有物理列清空且停止使用，保持已应用迁移校验和。

核心操作成功后尝试写报告，250ms 预算，失败只记录脱敏 warning。报告自身变化不触发核心写入、revision 或 audit；CAS/核心事务失败不发布新报告。运行报告丢失不阻断已选资源执行。获取/提交阶段不重建人工报告，避免过期后用新策略重解释旧选择；明确选择新来源才产生新报告。详情按需读报告，摘要/分页不读；独立 TaskStore.List 按每批 128 个 task ID 加载，避免每任务扫描诊断。单份 256 KiB，保留沿用 diagnostics 的 14 天/最新 100000 条，每批清理 1000。

本地停机备份后把现有报告包装为任务关联记录，清空核心旧摘要；不加入启动自动转换。旧独立 SQLite store 仍仅属于既有兼容/测试入口，不代表生产存储归属。证据见[报告存储复核](../reviews/2026-11-24-resource-selection-storage.md)。
