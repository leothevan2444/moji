## 代码核对：当前混在一起的职责

[AutomationConfig](../../internal/config/config.go) 同时保存任务执行开关/周期、资源重查周期、订阅检查周期、StashBox 顺序、发行决策和选种规则。[AutomationSettingsEditor](../../web/src/components/settings/SettingsPanel.tsx) 在同一个表单状态中编辑这些字段。

当前选种可分六个快速排序规则：站点偏好、标题匹配、发布日期、标题相似度、做种数、体积；另有单视频和文件名匹配两个文件检查规则，以及检查数量和规则链开关。实际调用见 [candidate selector](../../internal/taskruntime/candidate_selector.go)、[寻源执行](../../internal/taskruntime/service.go)、[硬身份验证](../../internal/taskruntime/torrent_validation.go)。快速/文件规则是实现阶段，不宜直接当作最终用户理解的顶层功能边界。

`INDEXER_PREFERENCE` 在结果取得后比较 TrackerID/Tracker，不控制请求顺序；[Jackett client](../../pkg/jackett/client.go) 当前仍用 all/results。StashBox 顺序由 [metadata.Service](../../internal/metadata/service.go) 统一使用，服务于演员映射、发现与订阅相关目录读取；排在配置列表外的已注册 endpoint 仍按 Stash 顺序追加，不能将优先级误解为禁用名单。

## 建议的 tab 与分区

| tab | 分区与配置归属 |
| --- | --- |
| 索引器 | Jackett 连接与状态；索引站点及查询顺序；逐站查询、失败与限流回退的明确行为 |
| 下载器 | qB 连接；下载位置/分类/标签；限速；做种与清理。资源挑选规则不因涉及 torrent 就归 qB 管理 |
| 媒体库 / Stash（名称待定） | Stash 连接与状态；元数据来源及 StashBox 优先级；路径映射与交付；字幕/生成资源。建议相关 StashBox 数据缓存配置归此处，高级分区呈现 |
| 任务与订阅（替代“自动化”的建议名称） | 订阅检查与发行处理；资源选择；无资源重查；后台任务推进及高级周期设置 |
| 系统 | 全局运行、开发者模式、跨领域图片缓存、任务删除等系统行为 |
| 日志 | 日志布局、级别、历史读取与实时跟随 |
| 关于 | 版本与项目说明 |

“任务与订阅”保留调度与策略关系，避免把剩余选种规则硬塞到下载器或索引器。暂不再增加很小的独立“种子”tab；若将来资源策略明显增多，再评估是否单独建页。

StashBox 归“媒体库 → 元数据来源”，与 Jackett 的资源索引站点明确区分。实例列表仍从 Stash 配置读取，Moji 配置使用顺序；本次不据此引入另一套独立的 StashBox 凭据管理。未来 UI/配置字段应体现“优先级”而非暗示选中/禁用；迁移需保留当前未列出源仍被追加的语义，改变则单独说明。

## “自动选种策略”改为“资源选择”的建议

| 当前配置 | 建议归属 | 语义要求 |
| --- | --- | --- |
| `fast_rules.indexer_preference.tracker_ids` | 索引器 → 查询顺序 | 演进为真实逐站请求顺序；不同时保留一份冲突的全局站点排序规则 |
| 标题匹配、发布日期、标题相似度 | 任务与订阅 → 资源选择 → 候选偏好与排序 | 虽来自索引器返回值，作用对象是候选资源；不是索引站点设置 |
| 做种数、体积及各排序方向 | 同上 | 当前是排序依据，不能在迁移时擅自变成最低做种数/体积硬阈值 |
| 单视频、文件名匹配 | 资源选择 → 文件内容偏好与检查 | 区分偏好、必须满足与无法检查；多部件本身不因支持单视频偏好就一概排除 |
| 检查候选数量 | 资源选择 → 检查预算（高级） | 是读取 torrent 内容的成本预算，不是每站搜索结果数，也不是 qB 并发下载数 |
| 规则链开关 | 资源选择 → 自动选择行为 | 先核实关闭应代表什么，再确定控件；不能把当前默认规则回退描述成完全关闭自动挑选 |
| 手动排除记忆（R-003） | 后续资源选择设计的输入 | 作用域和撤销等尚待讨论，不因本次分组自动产生全局黑名单 |

资源选择要讲清三层：不可绕过的身份/重复校验、用户偏好/排序、文件检查与无可接受候选时的处理。严格番号与精确 torrent 身份校验保留在执行层，不变成一个可关闭的设置。

当前 `AVOID` 主要体现排序降权，`LOCK` 也处于文件排名逻辑；不能直接承诺它们是硬排除或唯一锁定。当前关闭规则链时 selector 会恢复默认配置。R-002 必须用回归矩阵审查这些语义，再决定保留、更名还是调整行为，而非只搬字段。

逐站编排的建议流程为：当前站搜索 → 校验候选资格 → 候选偏好排序/有预算的文件检查 → 验证可用资源 → 满足停止条件，否则进入下一站。建议“查不到”以没有可接受候选为边界，不以收到任意模糊匹配就停止；此语义仍须在 R-001/R-002 中确认，失败/限流与空结果分别处理。

“资源选择”涵盖后台自动挑选与手动列表的规则解释/候选排序；手动选择不自动套用全部自动偏好，但共享硬身份校验，预览、实际提交和重试的差异必须明确。名称扩大不表示新增后台功能已实现。

## 配置与保存边界也必须拆分

当前 [saveAutomationSettingsSection](../../web/src/components/settings/SettingsPanel.tsx) 被三个独立外观的保存按钮共同调用，会提交整份 automation；后端 [UpdateAutomationSettings](../../cmd/moji/settings_store.go) 同时更新策略、来源顺序和周期。移动表单后不能继续由不同 tab 写同一个完整旧快照，否则可覆盖其他分区的新值或草稿。

建议配置职责为 `indexers`（连接与查询顺序）、`library`（连接、元数据来源、交付）、`downloader`（下载客户端设置）、`tasks`（订阅/发行、资源选择、后台执行），其余 system/logging 延续职责。这里只确定语义归属，精确 YAML key 和路由名待字段映射确认，不要求配置树机械复制 UI 的 tab 布局。

GraphQL 输入、config store 更新及前端 draft 应按有意义的业务分区保存，只提交该分区字段；原子文件写入仍保护整份 YAML 的一致性。qB 运行限速和核心库中的持久清理策略继续使用各自真实持久化方式，不因页面统一就强行搬入 YAML。

旧站点偏好转新查询顺序会改变“跨站排序”与“前站命中即停止”的关系，不能宣称纯结构无行为变化。需要说明规则优先级变化、未列出/失效站点如何处理，保留迁移前后可核对的有效配置与预期行为。

## 先确定统一设计，再覆盖所有 tab

需形成可复用的固定规范，至少包括：

- tab 层级、顺序、选中态、宽窄屏与路由行为。
- 页面标题、分区标题、子标题、hint 与配置项说明的职责和排版层次。
- 字体、字号、字重、行高、颜色、留白和内容宽度。
- 配置项 label、当前值、默认值、帮助、验证错误和敏感值显示方式。
- 输入框、开关、选择器、数值、排序控件、按钮与保存/测试连接操作的统一规格。
- 加载、未配置、连接失败、保存中、成功、部分失败和未保存草稿的交互。

优先复用或整理现有组件与样式 token，通过“索引器”及“媒体库/Stash”等代表性 tab 验证，再覆盖全部 tab。不保留每个 tab 各自决定字体、标题和 hint 的分叉。

保留现有 settingsClient 的新鲜读取、跨 tab draft、原子保存及失败恢复。按语义统一，不为视觉统一把不同作用域的保存或错误混成一次不可解释的操作。

## 配置与契约同步演进

从每个配置项建立旧字段 → 新字段 → 所属 tab → GraphQL 读写 → 运行 provider 的映射表，再改 Go 类型、config store、schema/resolver、Web documents/forms、示例配置、帮助与测试。

改变字段归属不能丢默认值、现有明确配置或未涉及字段；旧结构识别、同时出现新旧字段、冲突值和失败恢复需要明确规则。是否短期兼容旧结构在设计中说明，不提前假定正常启动会静默重写文件。

删除 connections 后重新确定默认设置入口；旧 `/settings/connections` 与 `/settings/ingest` 书签需要有清楚的迁移/重定向规则。UI 文案、URL 和 YAML 名称分别明确，不以改显示名称冒充结构改造。

## 实际旧配置迁移属于交付

用户已明确要求“做完以后帮我手动迁移旧配置文件到新结构上”。这是设置重构完成后的既定交付步骤；本次整合文档不执行迁移。

实施完成并验证后，识别实例实际加载的配置路径，保留可恢复原件；先在副本按最终映射迁移并验证新程序读取，再对实际旧配置执行迁移，核对服务连接、路径、策略、明确开关及其他未改设置保留。需要进程重载或重启时，按实际运行方式和已有授权执行，并记录结果。

凭据仍保留在本地受保护配置中，交付记录只包含迁移范围和验证摘要。不能以“新示例已更新”“兼容解析已写好”或“请用户自行迁移”代替实际配置迁移。外部服务无法核实时明确记录验证限制，不把它当作配置丢失或擅自改值。
