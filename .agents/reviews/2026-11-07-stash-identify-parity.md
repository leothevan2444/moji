## 阶段判断

番号回退复用 Stash 挖掘及保存 API，按照其识别默认值和来源覆盖值处理全部支持的刮削资料，包括封面、关联实体及资料图片。此前遗漏封面及 createMissing 的分支已经补齐；成功必须读取字段和图片字节核实。用户已明确接受 API 编排，Stash 负责最终校验与写库。

## 原生对照

## 恢复与边界

V2 计划冻结选中资料、有效设置、原始场景和封面摘要，先写核心外部命令，再调用 Stash。创建响应丢失按精确远程身份核对；场景保存响应丢失读取完整目标字段及封面，未完成 V1 用原远程 ID 升级而不改选。必填文字完整不能绕过已有未完成的图片保存计划。任务完成和命令确认在同一核心事务提交。

保留用户批准的“唯一精确番号”门槛：即使 Stash 允许多匹配取首条，Moji 仍保留人工处理；启用跳过标记时写标记。独立实体 API 与场景保存不具备原生 Identify 单库事务的整体回滚：后续冲突可能留下已经成功创建的关联实体，重试按远程身份复用。姓名/别名冲突不自动合并。Stash 设置或人工资料变化时拒绝旧计划覆盖。
