# 固定任一条件的资源规则

日期：2026-11-22。状态：已实现、验证并更新本机运行实例。用户明确要求规则允许多个匹配条件，且不允许配置规则内 ALL/ANY；任一满足即规则满足。取代同日[单项限制](2026-11-22-atomic-resource-rules.md)，过滤与层级仍归规则组。当前契约见[设计](../plans/resource-selection.md)及[用户指引](../../docs/resource-selection.md)。

## 实现

规则为 ID、名称、非空 conditions，每个条件独立选择 scope/value 或 minimum/maximum。删除顶层单项字段；没有规则 mode、条件 operator 或逐项否定。规则内固定 OR，命中即短路，其他未知不阻挡；无命中但存在未知为 UNKNOWN，全部不命中才为 NO。层级否定作用于整个规则，UNKNOWN 保持 UNKNOWN。

条件数量不限，总策略 192 KiB 及单候选 32 条证据边界保留，省略证据计数明确。每个条件的正则仍按完整 /…/ 识别，数值闭区间和 GiB 编辑沿用。策略及解析版本为 4，Go/YAML/GraphQL/Web/生成产物同步；历史报告不重新执行，v3 人工报告原样保留。没有新增数据库 schema 或生产自动配置迁移。

规则编辑窗口提供条件卡片、添加与删除按钮，固定任一说明，不显示规则内组合选择。至少保留一个条件；混合字段、数值输入、共享规则删除保护、自动保存和返回焦点保留。

## 本机配置

一次性转换先将当前单项规则包成单条件，再只对上次拆分产生、名称未改且在所有引用位置均以正向 ANY 使用的完整同胞集合重新合并；不根据任意名称猜测，不把 ALL 或否定引用误并成 OR。预演 22 条规则恢复为 7 条，22 个条件完整保留，当前用户内容不由历史值覆盖。20,000 组输入对照转换前后资格、优先层级与未知状态一致，其他配置语义完全相同；正式写入前使用新 loader 校验，备份后原子替换。
