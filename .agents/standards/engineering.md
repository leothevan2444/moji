# 工程规范

状态：项目规范；建立于 2026-11-01，依据 `71ef6fa`。适用于源码、契约、数据、测试、依赖和交付。产品取舍按 [体验规范](product.md) 向用户复核；现有结构的评价与问题证据见 [架构复核](../reviews/2026-11-01-project-standards.md)。

## 架构与代码组织

- 保留当前单进程、按业务领域分包的结构。先找生产调用路径和已有实现，再决定改动位置；领域服务不依赖本项目 Moji API 的 generated model 或 React 状态，传输层不承担发行、选种、入库等规则。当前使用上游 Stash/StashBox 的生成模型属于既有客户端耦合，不等同于依赖 Moji 传输层；只在确有独立领域语义时就近转换，不为消除所有上游类型复制整套模型。
- 依赖组装和 worker 生命周期归 `cmd/moji`；创建意图归 taskflow；执行状态机归 taskruntime；订阅/发行归 subscription；媒体产物归 mediafiles，Stash 操作归 stashsync；存储基础设施归 storage，协议适配归 pkg。具体地图见 [architecture.md](../architecture.md)。
- 新任务经 taskflow，不在 resolver、页面、订阅或发现中复制任务创建/去重。任务状态机保持一个所有者，不能为了拆长文件把同一阶段状态复制到多个服务。
- 接口放在消费边界，优先表达当前用到的窄能力；新增领域不继续扩张“包含所有读写操作”的统一接口。重构先缩小受影响调用方，不要求一次替换所有兼容接口。
- 路由负责 URL/页面组合，领域 hook 管理数据与同步，组件表达交互，纯转换放就近工具模块。持久真值、服务器观测、前端缓存和临时交互状态分别所有；不要因跨组件共享就全部提升成全局状态。
- 文件按责任命名。多个独立业务分支、重复转换/控件或修改波及不相关功能时，再按职责拆分。文件行数是调查线索，不是质量结论或强制拆包阈值。
- 复用有相同语义的代码，不把仅有表面相似的业务做成复杂泛型框架。不为预计的未来需求引入通用 job、事件重放系统、新数据库/服务层或第二套 UI/状态框架。
- 本地改动沿用已有命名、格式、错误包装及目录约定；Go 改动 gofmt，不夹带全仓格式化、无关改名或大规模搬目录。新增共享抽象必须有真实消费者及清楚职责。

## 契约与类型

- API 明确输入资格、批量上限、排序/分页、字段单位、未知值、逐项结果和稳定错误代码。标题、客户端来源元数据与浏览器日期不代替服务器的业务校验。
- 区分缺省/null、空字符串、空列表、false、0；更新只作用于请求明确提交的字段，不能用旧的整份快照覆盖其他分区的新配置。设置变更延续 typed patch、验证后原子保存和待保存编辑保护。
- schema/操作源、resolver/mapper、前端绑定和相关测试在同一变更演进。先生成再编译，不手改生成文件；新增字段考虑旧读取方，兼容范围由真实消费者决定。
- 类型转换局限在明确边界，集中校验外部数据；不通过 `any`、伪造完整模型、忽略类型错误或到处加可选字段掩盖缺失契约。现有运行快照/传输映射可增量收敛，不为消除所有映射引入一次性大重写。
- 重命名或改变规则含义时检查 Go、YAML、GraphQL、Web、i18n、测试与文档。不得重新引入用户已明确要求移除的旧枚举/兼容路径，也不擅自删除仍在使用的真实契约。

## 持久化、外部副作用和恢复

- 生产持久化统一使用 storage.Manager 注入的 owner；重要身份、选择、授权、取消、删除/外部操作意图留在核心库，进度观测和缓存按各自恢复角色存储。
- 决定先持久化再执行外部副作用，记录可核对身份与结果。请求超时可能已执行；重试需要幂等或观察核对，不能因错误响应就改选另一资源或反复执行删除。
- 任务变更保持 revision/CAS 与 generation fence；一个事务提交需要原子的决定和审计，不依赖跨数据库、文件与网络事务。网络/媒体操作不能占据 SQL 事务。
- 新增有序、不可改写的迁移；未知/未来 schema 和 payload 明确拒绝，支持的升级必须验证保留数据与恢复。源 schema、旧兼容 store 与 Manager 迁移不是同一入口。
- 配置使用既有原子文件写入及失败恢复。涉及实际数据或配置迁移时保留可恢复副本，先验证转换再激活，按任务已有授权完成交付；不能以更新示例代替要求的实际迁移。
- 存储瞬时时间保持统一，发行日期等日历语义走 `internal/releasedate` 的业务时区。未知日期/状态不猜测，浏览器不独立决定任务是否可创建。
- 上游失联保留最近确认事实，不能视为种子消失、订阅取消、影片没有入库或命令失败。清理、交叉做种与产物所有权继续遵守领域保护。

## 异步、查询与性能

- 已接收后台工作的生命周期绑定应用 context，HTTP 请求结束不撤销已接收工作；可取消任务明确取消范围。新增 goroutine、timer、订阅和后台刷新必须有所有者、取消和退出/等待路径，不用裸 `context.Background()` 绕过生命周期。
- 每个作业明确重启后继续、重新核对还是标记中断；不要求所有领域统一续跑。失败和关闭不能发布未持久化成功，事件不能代替持久进度。
- 网络调用与工作队列有取消、超时、并发/容量预算及适合该上游的退避；不把数据错误、空结果和限流混成一个可无限重试的分支。
- 复用各领域现有快照/事件/受控轮询，新增页面不能自行加无限刷新或全量拉取。断线、序列缺口、溢出和迟到响应需要有限范围的恢复；临时缓存不能成为业务真值。
- 列表在数据拥有方尽量筛选/分页，详情按需读；工作批次、缓存、订阅缓冲和历史保留有界。UI 分页不证明上游查询有界，也不意味着可以把全量读取换个名字塞进缓存。
- 性能变更依据真实调用、代表性数据、请求数/响应量/耗时评估；规模承诺必须附负载条件。避免为毫秒级猜测或小型静态数据引入复杂缓存/并发。

## 安全、诊断与依赖

- 凭据、配置、DB/WAL、日志、备份和本地测试材料不进 Git。签名 URL、密钥、Cookie 和完整敏感上游响应不进入普通日志、提示或截图；诊断保持可关联但脱敏。
- 不信任浏览器提交的可变元数据、任意路径或上游链接。采用已有身份、目录包含关系、URL 协议/来源和权限检查；验证后才提交外部命令。
- 日志保留任务/作业 ID、阶段、稳定代码和必要上下文；正常不变观测不反复记录业务历史。区分可丢弃诊断、实时事件和重要审计。
- 新依赖说明解决的问题、已有能力为何不足、运行成本与许可影响，更新 manifest 和锁文件；生成/构建工具遵循固定版本与现有 Make/scripts/CI，不另维护隐式命令链。

## 验证与变更交付

1. 改动前确定用户行为、领域不变量和受影响契约。修复缺陷尽量用能暴露问题的回归场景证明；不要堆与实现逐行对应或仅用于通过覆盖率的测试。
2. 默认使用 fake/httptest、临时数据根与合成数据；真实上游和破坏性测试必须显式 opt-in，不能只换端口却使用真实凭据/媒体目录。
3. 按 [开发流程](../workflows/development.md) 选用领域/契约测试、完整 suite、必要 race、生成、build、i18n、浏览器或媒体测试。涉及界面时另按产品规范走查，截图不能替代状态/行为测试。
4. 核心数据、迁移、外部命令、后台恢复或共享契约改动要覆盖成功、失败和边界；按风险验证并发/重启/重复提交。通过的检查不反复运行，除非新改动或未解决问题需要再验证。
5. 精确记录验证环境、命令和限制。缓存通过、skip、本机/容器、架构、静态审阅、CI 与运行验收分别表达；环境报错不直接判成产品回归，也不能记为已通过。
6. 同一变更更新对应的当前模块契约，未完成工作只写 TODO，重大决定与日期证据写 review/plan。规范不复制每个功能的历史流水账；发现旧文档失实就修正，并保留历史快照的时点。
7. 结束前查看完整 diff、未跟踪文件和敏感内容，检查生成一致性及 `git diff --check`。交付说明实际变化、原因、验证与未完项；用户要求提交时提交相关文件并核对工作区，推送/发布/运行更新按任务授权分别执行和报告。

## 架构问题的严重性与处理尺度

| 级别 | 判断依据 | 处理方式 |
| --- | --- | --- |
| P0 阻断 | 有证据的关键数据损失、错误外部副作用或核心流程无法使用 | 优先保全与修复，说明证据和影响；产品取舍向用户复核 |
| P1 高 | 系统性的正确性/验证缺口，或已确认的核心读取/运行规模边界 | 明确受影响路径、验收和可复现证据，纳入 TODO |
| P2 中 | 职责/接口/样式耦合让正常功能改动容易波及其他领域 | 沿实际需求小步收敛，不单凭行数全盘改写 |
| 低影响 | 不改变理解和行为的局部风格或个人偏好 | 就近处理或保留，不占据架构路线图 |

审视必须同时记录已做好的边界、问题证据、真实/潜在影响与验证局限。没有证据的“可能更优雅”不构成重构项目；不得把本次规范任务扩大成未经请求的业务/基础设施重构。
