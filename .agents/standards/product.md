# 产品体验规范

状态：项目规范；建立于 2026-11-01，依据 `71ef6fa` 的界面、领域实现及现有视觉基线。适用于新增、重构、修复和文案修改。它定义交付约束，不表示本轮重新设计界面；具体能力仍以相关模块和代码为准。

目标：用户顺着自己的目标完成操作，知道当前状态和下一步，不需要理解 Moji 的内部实现。执行入口、工程边界见 [主指引](../AGENTS.md) 和 [工程规范](engineering.md)。

## 先核实事实，再写用户文案

1. 写文案前追踪控件/路由 → GraphQL → 领域行为与持久状态，核对相关测试。确认操作影响范围、何时生效、是否可取消、失败如何恢复及实际限制；无法核实的承诺不写。
2. 将事实翻译成用户的目标、状态或后果。普通页面不出现 GraphQL、SQLite、快照、队列、轮询、防抖、revision、幂等、checkpoint 等解释实现的术语。配置确实需要的地址、API key、路径、正则及外部服务名称可以保留，并用用户语言说明用途。
3. 每段正文必须回答一个实际问题：这是什么、为什么需要我处理、这个选项有什么非直观后果、下一步做什么。标题/控件已经说明的内容不再复述；没有新增信息的 hint、摘要、欢迎语和功能宣传删除。
4. 默认不增加介绍段、卡片副标题、状态胶囊或“高效管理”等修饰。说明仅用于作用范围、非直观行为、代价和操作后果；不是每个字段都要配说明。
5. 使用短句、具体动作和现有领域词汇。相同对象在标题、按钮、确认、错误和帮助中同名；不把内部枚举或日志文本直接当用户文案。新增业务名称有歧义时按下文复核。
6. 已接收、处理中、完成分别表达。收到请求不能写“已下载/已入库”，连接测试通过不能承诺全部流程正常；未知不显示为 0，无资源、未发行、连接失败也不能互相替代。
7. 正常空闲和成功自动保存不长期占位说明；保存中、未保存失败、需要人工处理的结果必须可见。短暂提示不能成为长任务、失败或人工决定的唯一状态来源。
8. 错误优先说明用户受到什么影响及可行下一步；细节、关联标识和日志入口按需展开。不能因为“技术无感”隐藏失败、捏造完成或把所有错误都写成“稍后重试”。

以下是表达方式示例，只有实际行为满足条件时才能使用，不是要求全站替换固定句：

| 实际事实 | 面向用户的表达 |
| --- | --- |
| 已接收后台检查，之后可能创建下载任务 | “正在检查发行”；在对应位置持续展示进度 |
| 下载器暂时无法更新，仍有最近确认数据 | “暂时无法更新下载状态”，保留原内容与重试入口 |
| 自动保存失败，编辑值仍保留 | “设置未保存”，提供重试；不显示成功提示 |
| 同一目录在不同服务中使用不同路径 | “同一目录在 Moji 和 Stash 中的路径” |

文案通过 i18n key 表达，中文与英文同步核对，避免机械逐词翻译。qBittorrent 官方状态及 `faBinoculars` 等已确定约定继续遵守。资源与错误映射入口见 [Web 模块](../modules/web.md)。

## 沿用现有视觉语言

开始绘制前先找最接近的现有页面、同类组件和截图，对照布局、信息层次、动作权重、字体、间距、圆角、边框和状态色。截图用于视觉参照，文案与行为需回到当前代码核实；过期截图不能覆盖现行产品决定。

| 设计要素 | 现有权威来源与规则 |
| --- | --- |
| 颜色、主题、字体 | [theme.css](../../web/src/styles/theme.css) 的 surface/text/muted/line/accent 等变量；浅色与深色同时成立 |
| 间距、圆角、动效、层级 | [_tokens.scss](../../web/src/styles/_tokens.scss)、[_mixins.scss](../../web/src/styles/_mixins.scss)；沿用 4/8/12/16/20/24 间距阶梯及现有层级 |
| 设置外壳、分区、字段与保存反馈 | [SettingsPanels](../../web/src/components/settings/SettingsPanels.tsx)、[SettingsTabCommon](../../web/src/components/settings/SettingsTabCommon.tsx)、[settings-shell.scss](../../web/src/styles/settings-shell.scss) 与 settings 样式 |
| 抽屉、确认、焦点 | [Drawer](../../web/src/components/layout/Drawer.tsx)、[useModalFocus](../../web/src/hooks/useModalFocus.ts)、现有确认组件 |
| 图片、候选链接、种子状态 | 复用 SceneArtwork、TorrentCandidateLinks、CandidateSeeders 与统一 qB 状态映射；入口见 Web 模块 |

- 中性背景和文字承载主体信息，强调色留给当前选择与主要动作；成功、关注、危险沿用已有语义色。一个局部动作区要有清晰的主次，不能让每个指标、按钮和标签都成为视觉焦点。
- 不为新功能单独引入一套配色、字体、阴影、圆角、按钮或图标风格。先复用语义变量和组件，缺少共享能力时沿现有体系扩展；历史硬编码颜色不构成继续复制的理由。
- 对齐同层标题、字段 label、说明与控件，不混用相近但不同的字号和边距。设置页字级适用于设置作用域，不强制套到影片标题或任务卡片。
- 信息分区按用户任务划分，避免同一信息重复成两张卡、卡片层层嵌套或为了填满区域增加文案。保留已确定的顶栏、设置侧栏和二级页签模式。
- 检查完整页面及相邻组件的视觉平衡，不能只让新组件的孤立截图成立。窄屏有明确的信息顺序，长标题、空封面、缺失值和长错误不会挤掉主要操作。
- 动效只帮助理解真实变化；优先稳定位置、保留内容和渐进更新。遵循 reduced-motion，不能靠假进度、持续闪烁或装饰性动画制造“流畅”。

## 用用户路径复核交互

新增功能或改变流程/状态时，先用一段简短路径写清“用户想完成什么 → 从哪里进入 → 看到什么 → 做什么 → 结果在哪里 → 能否继续或返回”；它是内部设计/测试依据，不自动变成页面介绍文案。局部文案/样式修复可沿用已有路径核对，不要求另写长设计稿。实现后按相关场景逐步走查：

| 场景 | 必须能回答的问题 |
| --- | --- |
| 第一次进入 | 主动作可发现吗；空态与尚未加载有区别吗；是否要求无关前置操作 |
| 发起操作 | 点击后立即有反馈吗；重复点击/另一窗口会怎样；按钮禁用是否有可理解的原因 |
| 等待与更新 | 最近可用内容是否保留；完成的是本次请求还是业务工作；是否无故跳页、跳位或丢焦点 |
| 刷新、关闭、切换页签、前进后退 | 已接收工作能重新找到吗；筛选、分页、选择和未保存编辑是否按既有契约保持 |
| 部分成功和失败 | 哪些成功、哪些需要处理；失败项是否仍可查看/重试；能否在原位置继续 |
| 取消与离开 | 取消什么、已产生的结果是否保留；关闭面板是否只是停止查看；返回来源页是否连贯 |
| 键盘、移动、长内容 | 焦点顺序和返回点是否正确；只用键盘可完成吗；菜单、滚动与操作不冲突吗 |

现有交互契约必须保持：

- 后台作业从后端持久状态恢复，不用按钮 fetching 或 localStorage 假装活动任务；具体重启行为按领域定义。
- 路由和 URL 管理可返回的页面/详情状态，打开抽屉不丢来源页。跨页选择按稳定 ID 保持，不能按可见列表裁剪；批量结果保留未成功项。
- 自动保存沿用现有串行增量队列与共享状态组件，延迟响应不能覆盖用户新编辑；切换分区不丢待保存项。测试当前输入与已保存连接状态必须区分。
- 断线时保留最近确认状态，并说明需要更新；正常连接不常驻技术状态。一个分区失败不挡住其他可用内容。重试前核对原操作是否可能已执行。
- 复用统一的对话框、菜单和焦点管理。icon-only 动作有可访问名称，重要状态不只靠颜色，确认说明真实后果。

## 产品取舍必须向用户复核

遇到会改变用户理解或实际结果的选择时，向项目所有者提出简短问题，给出建议、可选方案和各自影响；不要把选择藏在实现中。典型情形包括：

- 新增/更改主要入口、业务名称、流程顺序、取消/关闭含义或默认自动执行行为。
- 在自动下载与人工复核、准确性与速度、首次等待与完整结果之间改变承诺。
- 改变匹配、排除、重试、历史保留、删除、权限或持久决定的作用范围。
- 缺少产品真值，需要猜测未知状态、生成新策略或决定是否接受数据/功能降级。

先查看本会话与已确认契约，已有决定直接沿用，不重复询问。常规的组件复用、遵循现有 token、修复已确认行为的缺陷和局部技术实现可自行推进。只有依赖该产品选择的实现等待答复，源码调查、可逆准备和无关工作继续；没有答复不等于同意。

## 合入前的体验检查

按 [开发验证](../workflows/development.md) 选择检查，审阅变更涉及的文字和真实交互，不用“测试全绿”代替体验走查：

1. 每句新增说明有源码依据，删掉重复和技术实现叙述，保证中英文含义一致。
2. 对照同类现有页面检查色彩、层次、密度和主要动作；新建与重构采用同样标准。
3. 走通主路径及相关等待、失败、部分成功、刷新和返回场景，核对可访问性。
4. 可见变化复核相关桌面/移动、深浅色及必要长文案/pseudo/RTL 截图；说明哪些是自动化、哪些是人工检查。不能用放宽截图容差、更新无关基线或隐藏错误换取通过。
