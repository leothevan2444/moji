# 阶段复核与跨会话交接

阶段复核用于回答“代码现在做到哪、证据是什么、边界在哪里”。它不是每天重复生成的进度报告，也不授权运行生产维护操作。

## 何时复核

- 用户要求项目审计、重新规划或重写指引。
- 跨模块能力完成、存储/事件协议迁移、运行与发布方式改变。
- 旧 TODO 大批完成，或代码与现有指引明显不一致。

局部修复更新相关模块和 TODO 即可，不必每次创建新的全项目复核。

## 核对顺序

1. 记录日期、完整/短 commit 和 dirty 状态，明确审查的是源码、工作树、运行二进制还是某次 CI。它们可能不同。
2. 从入口追踪真实链路：启动与关闭 → GraphQL → 领域 → managed store → worker → Web 数据与操作。先找生产调用方，再读兼容实现。
3. 对照旧结论逐项找实现和回归证据，区分“已解决”“部分解决”“仍存在”“仅有提案”；不能把旧 P0 机械继承。
4. 验证影响结论的边界：身份、重复、失败、取消、重启、快照恢复、分页、部分成功。按 [验证矩阵](development.md) 选命令，记录具体环境与 skip。
5. 把稳定决定吸收到模块，把真正未完成工作放进 TODO；复核只通过稳定 ID 引用后续问题。
6. 验证所有链接，检查 Git 可见性及 diff。新的复核完成后更新主入口与 TODO 的最近复核链接。

## 复核模板

复制以下结构到 `reviews/YYYY-MM-DD[-topic].md`，删掉无关段落，使用实际结果：

```markdown
# 阶段复核：主题（日期）

基线：commit / 工作树状态；范围：源码、测试、CI 配置或运行实例。

## 阶段判断

一句话描述已经闭环的用户能力，以及尚不能承诺的部分。

## 旧结论校准

| 旧判断 | 当前事实 | 源码或回归证据 |
| --- | --- | --- |

## 验证

| 检查 | 实际命令及环境 | 结果/限制 |
| --- | --- | --- |

## 剩余边界

只描述当前证据，后续动作链接到 TODO 的稳定 ID。

## 文档变化

模块更新、过期文档处理、提案状态。
```

复核不包含凭据、生产绝对路径、临时 PID 或完整运行日志；运行证据可留在外部受保护位置，文档只记录足以评估结论的摘要。不要把以前的测试结果冒充本轮实测。

## TODO 与交接约定

TODO 项使用 `状态 + 证据 + 验收 + 下一步`，例如：

```markdown
### G-123 · 问题名称

状态：待处理；建议优先级：P1。
证据：当前调用路径/相关测试。
验收：可观察结果和必要边界。
下一步：一条明确可执行的动作。
交接：仅进行中时填写已改文件、验证、剩余和阻塞。
```

需要多阶段设计时单独建 `plans/<topic>.md`，开头标明提案/实施中/已落地，列出与当前实现的差异。实施状态和下一步仍在 TODO 维护；不要在模块、提案、review 各复制一份活动 checklist。

本轮任务已经完成时，在新 review 或提交记录中留证并从 TODO 移除；不要为了充满列表而保留所有完成事项。暂时受阻必须记录具体条件，不能只写“继续优化”。
