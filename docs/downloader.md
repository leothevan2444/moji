# 下载器管理

Moji 在主页提供下载器统计，通过“查看种子列表”打开种子管理弹窗，在 `/settings/downloader` 配置清理和限速，qB 继续负责 BT 协议和文件下载。
支持 qB 5 的 start/stop API；旧版返回 404 时回退到 resume/pause。
会话过期或 qB 重启后自动重新登录；初次登录失败不会阻止 Moji 启动。
仅在明确收到 403 时重新认证并重试，不重试结果不明的超时写操作。

- 每 3 秒独立监控一次，包括已完成 Moji 任务对应的种子；主页、列表和任务详情每 3 秒读取后台快照。任务状态复用同一份 qB 列表更新，不等待入库处理周期。
- 种子列表以 qB 最近成功同步时仍存在的种子为主，按 Hash 匹配关联 Moji 任务；未关联的 qB 种子仍显示，找不到 qB 种子的 Moji 任务不补入列表。筛选、数量和分页均遵循这一范围。任务详情继续保留种子丢失与清理记录。
- 桌面使用独立种子列和关联任务列的表格；手机使用紧凑列表。详细信息按需展开，启停之外的操作集中到“更多操作”，移除操作仍需确认。
- 显示上传/下载速度、分享率、累计做种时间、传输量、ETA、连接的 seeds/peers、可用副本数、分类、标签、路径及关联任务。
- 支持启动、暂停、重新校验、重新汇报 Tracker、全局速度限制和种子移除。
- 移除、删除文件和重新校验需要在页面中确认；命令提交后以 qB 的下一次观测为准。
- 下载中的种子丢失或出现 error/missingFiles 时，任务进入受阻状态；恢复后自动继续。其他入库阶段仍显示种子状态，不会因此回退已完成的入库工作。已完成任务的种子丢失和源文件缺失显示为中性信息，不计入异常。
- qB 连接失败不会视为全部种子丢失；显示最近成功快照和过期提示，停用操作按钮。
- qB 列表观测与任务同步分开执行。任务数据库暂时不可用时继续更新 qB 列表，保留上次关联任务信息，并暂停自动清理；后台任务同步只保留最新一批观测。
- 页面读取最近快照不等待正在执行的 qB 请求。快照写盘失败会单独报告，当前进程仍提供最新观测；重启后只能恢复最近成功写盘的数据。删除意图必须先成功持久化，才能发送删除命令。
- 重试添加种子被 qB 拒绝时，按已验证的精确 info hash 查询已有下载，匹配成功则关联实际进度和路径；其他种子不会按标题猜测关联。

## 种子状态文案规范（全项目）

所有展示 qBittorrent 种子状态的页面、弹窗、任务卡片、生命周期详情及后续新增入口，
必须使用 qBittorrent 官方 WebUI 的状态映射和简体中文翻译，逐字一致，
包括 `[F]` 前缀、大小写和空格；不得自行改写为近义词或直接展示 API 状态码。
统一调用 `web/src/utils/qbittorrentState.ts` 的 `qbittorrentStateLabel`，
任务搜索同时支持官方文案与原始状态码。

当前依据 qBittorrent `release-5.3.0` 的
[状态映射](https://github.com/qbittorrent/qBittorrent/blob/release-5.3.0/src/webui/www/private/scripts/dynamicTable.js)
及 [官方简体中文翻译](https://github.com/qbittorrent/qBittorrent/blob/release-5.3.0/src/webui/www/translations/webui_zh_CN.ts)
（`TransferListDelegate` 上下文；未知状态使用 `HttpServer` 的 `Unknown`）。
兼容旧版 `pausedDL`、`pausedUP` 时使用 `release-4.6.7` 同路径的官方映射及翻译。
例如 `stalledUP` 显示“做种”，`stalledDL` 显示“等待”，`pausedUP` 与 `stoppedUP` 均显示“完成”。
未识别状态使用官方默认文案“未知”。

`web/src/utils/__fixtures__/qbittorrent-statuses.json` 保存独立提取的官方文案、
版本链接和源文件 SHA-256；`qbittorrentState.test.ts` 校验每个状态的中文及英文文案，
并覆盖任务摘要和生命周期显示。升级文案时应从官方状态分支及对应翻译上下文重新核对并更新这些依据。
Moji 的 `missing`（种子丢失）、`removed`（已移除）属于自身观测状态，
Moji 工作流的下载、入库等阶段属于任务生命周期，均不冒充 qB 官方状态。
API、数据库、日志及诊断导出保留原始状态码，供状态判断和排障使用。

## 传输设置

“传输设置”页签分为三个区域：

- 全局速度限制：下载和上传上限，单位 KiB/s，0 表示不限速。
- 做种限制：分享率、累计做种时间、非活跃做种时间，以及达到限制后的动作。时间单位为分钟；qB 提供条件组合时，可选择任一或全部条件达到。
- Torrent 排队：最大活动下载数、上传数和种子数（-1 表示不限），以及慢速种子排除、下载/上传速度阈值（KiB/s）和非活跃计时（秒）。

做种限制及排队直接修改 qB，自动保存，不在 Moji 中执行对应业务。在 qB WebUI 中修改后，重新进入设置会读取当前值。当前 qB 未提供的选项不显示；读取失败可重试，其他设置仍可使用。

**qB 的移除动作由 qB 自行执行，不等待 Moji 入库完成。** 若希望由 Moji 保护入库内容，可让 qB 达到做种限制后停止种子，再使用 Moji 自动清理。

## 自动清理

默认关闭。启用后，在“清理条件”下拉框中选择一种方式：

1. **入库完成后立刻清理**：所有关联任务完成入库后的下一次同步执行，不等待容量条件。
2. **下载盘空间不足时清理**：剩余空间低于或等于阈值时触发，超过阈值后停止。阈值单位 GB，1 GB = 1,000,000,000 字节。

容量清理可选高磁盘占用、高分享率或高做种时间优先。分享率和做种时间只用于排序，Moji 不再按它们的阈值触发清理。磁盘占用以 qB 报告的已完成数据量估计；每轮最多清一项并重新读取真实空间，不假定种子大小就是释放容量。

容量清理使用 qB 默认下载盘指标，只处理保存路径与默认下载目录一致的种子，不覆盖自定义目录或所有磁盘。容量条件必须同时删除下载源文件，启用时会选中并锁定此选项。选择入库完成后立刻清理时，不使用容量阈值和排序设置。

所有自动清理均要求至少关联一个 Moji 任务且全部关联任务已入库；未关联种子不自动清理。校验、移动文件过程中不清理；立刻清理可以移除已完成移动入库、源文件已缺失的旧种子。

删除文件需确认使用 copy 或 move 入库且已经完成，本机可访问的源和入库目录独立、不是同一文件，且无其他 qB 种子引用重叠源路径。检查失败保留种子和文件。未完成入库的关联种子禁止手动移除。Moji 任务记录和已入库内容保留。

正在获取元数据或已停止／暂停下载的种子，仅在内容路径为空、进度／已完成数据量／大小均为零，且 qB 文件接口明确返回非 null 的空列表时，才不会阻塞其他种子的清理。普通种子路径未知、文件列表非空、查询失败或无法完成核对时仍保留保护。文件列表查询共用两秒总超时，不限制种子数量；核验超时或读取失败会显示对应原因并保留源文件。核验结果不跨轮复用，删除前会重新读取 qB 列表并复核，避免元数据期间就绪后遗漏共用文件。

主页在剩余空间旁使用扫帚图标表示自动清理。正常时为灰色静止图标；实际执行或短暂核对时显示“清理中”并动画；受阻时显示橙色“清理受阻”；明确执行失败时显示红色“清理失败”。关闭时不显示空闲图标。系统启用减少动态效果时不播放动画；状态无法更新时也会停止动画。

悬停或键盘聚焦显示简短原因，点击直接进入自动清理设置，不另开详情窗口。主页不再常驻大段清理说明；不把请求超时当成已确认失败。

删除前持久保存意图，再核对 qB 种子是否消失。结果不明时只核对同一 hash，不改删其他候选；确认超过 15 秒后停止动画并显示受阻。qB 明确拒绝请求或清理记录保存失败才显示失败；明确拒绝后有 30 秒重试冷却。

容量清理在确认种子移除后观察 6 秒，再读取真实空间。一次空间未净增加不会永久阻塞；仍不足时继续逐项清理。连续 3 项都未观察到空间净增长时暂停进一步删除，提示“未观察到空间回升”。之后观察到空间回升，或用户关闭后重新启用策略，才重置预算。达到容量阈值以上也会重置预算。净空间变化可能包含其他下载或程序写入，不能据此诊断文件被进程占用或磁盘快照未释放。

两种清理方式使用相同的执行状态。进行中的删除意图、观察截止和无进展预算都保存在核心库，重启或重建运行缓存不会丢失；任务、空间或目录无法核对时保留保护，不启动新的删除。

没有可安全清理的内容时，主页图标显示受阻，详情展示原因，可扩容、清理其他占用或等待入库完成。本功能不自动暂停下载，不能保证其他程序持续写盘时仍有容量。

自动清理配置保存在 `config.yaml` 的 `downloader.cleanup` 中，页面保存后在下一轮清理检查中生效，无需重启。直接修改 YAML 文件后需重新启动进程读取；运行中请使用设置页保存，避免内存中的旧配置覆盖手动编辑。

```yaml
downloader:
  cleanup:
    enabled: false
    trigger: AFTER_INGEST
    delete_files: true
    min_free_gb: 50
    capacity_order: DISK_USAGE
```

`trigger` 可选 `AFTER_INGEST`（入库后）或 `CAPACITY`（空间不足）；`capacity_order` 可选 `DISK_USAGE`、`RATIO`、`SEED_TIME`。容量方式要求 `delete_files: true`，阈值必须大于 0。省略配置时默认关闭，不从数据库读取旧配置，也不自动转换。

删除意图及空间确认保存在核心数据库；最近观测保存在运行数据库。不保存每次空间检查的历史时间序列。

## 存储指标的含义

剩余空间来自 qB `/sync/maindata` 的 `free_space_on_disk`，表示 qB 默认下载盘的空间，
不是 Moji 容器所在磁盘，也不覆盖所有自定义下载盘。
“种子已完成数据量”和“待下载数据量”为 qB 报告值之和。预分配、硬链接、交叉做种、
未选择的文件及磁盘上其他文件会影响实际占用，因此不能据此计算准确的磁盘占用率。
接口未报告空间时显示未知。

## 同步与数据库负载

不变的任务轮询不更新任务行、更新时间或历史事件。纯进度变化仍保存任务进度并推送实时事件，
持久化历史只记录阶段、状态等实际变化，避免每分钟为每个任务重复累积历史。
写事务使用 `BEGIN IMMEDIATE` 提前取得写入资格，避免读完旧 WAL 快照后升级写事务失败；
首页汇总使用只读事务，继续允许其他连接写入。
历史数据不会由此次修复自动清理。

## 种子元数据请求

同一主机的元数据下载共用串行队列，请求完成后至少间隔一秒；经 Jackett 的 `/dl/<indexer>/`
下载按 indexer 分组，避免一个来源限流阻塞所有来源。
遇到 429、5xx、网络超时或 Jackett 下载接口的 404 时，采用从 30 秒开始的指数退避，
最长 8 分钟，并遵守最长一小时的 `Retry-After`。冷却期间跳过同一来源的后续请求，
不逐条重复记录冷却日志。Jackett 的 404 可能掩盖上游限流，因此会保守退避。
限速和退避状态只保存在当前进程中，重启后重新建立。
网络错误日志只保留主机与底层错误，避免输出签名 URL 中的 API 密钥。
