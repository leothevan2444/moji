# 发行复核入口

该方案已获确认并实现。入口位于演员页面的“发行复核”，独立地址为 `/performers/review`。原“记录供复核”记录在读取时迁入独立的持久复核记录，不自动创建任务。

## 入口与布局

主入口放在「演员与订阅」页面工具栏：**发行复核 · 12**。数字按影片去重，仅统计真正需要人工确认的发行，不包含策略跳过或任务创建失败。

点击打开可通过独立 URL 返回的发行复核视图，沿用演员页的页面结构，不新增一级导航。演员卡片和详情中的“待复核 N 部”作为快捷入口，打开同一视图并按演员筛选。移动端使用卡片布局。

默认只显示待复核影片，可按演员、番号／标题、VR 属性及处理状态筛选。另有“已下载”“不下载”“策略跳过”历史视图。“未能创建任务”单独展示失败原因和重试入口，不混入待复核数量。

```text
演员与订阅 / 发行复核                         待复核 12 部
[演员：全部] [VR：全部] [搜索番号或标题] [状态：待复核]

□ ABCVR-123   影片标题                         [VR]
  演员甲、演员乙 · 2026-10-20
  需确认原因：VR 策略为人工确认
                                   [下载此片] [不下载]

已选 3 部                              [下载所选] [不下载所选]
```

每条显示封面（已有来源可用时）、番号、标题、发行日期、相关演员、VR 标识、复核原因、来源链接和发现时间。复核原因使用可读文案，例如“VR 策略为人工确认”“多人作品需确认”“超出自动下载时间范围”“发行日期不明确”。

影片列表跨演员去重。同一影片因多位演员的订阅而出现时，只处理一次，并同步所有关联演员的记录。分页和筛选变化保留明确的跨页勾选集合；提交完整所选集合，返回逐条结果。

## 处理行为

| 用户操作或事件 | 发行记录结果 | 是否新建任务 |
| --- | --- | --- |
| 尚未处理 | 待复核 | 否 |
| 下载此片 | 已确认下载，关联任务 | 是 |
| 不下载 | 已拒绝下载，记录处理时间 | 否 |
| 自动策略为跳过 | 策略跳过 | 否 |
| 已存在同番号任务 | 关联已有任务并显示状态 | 否 |
| 已在 Stash 库中 | 已入库，移出待复核 | 否 |
| 创建任务失败 | 保留可重试记录与失败原因 | 否；若已创建则返回并关联已有任务 |

用户点击“下载此片”就是对当前影片的明确授权，不重复套用自动策略或再次询问；提交前由后端重读发行记录，检查是否已处理、已有任务或已入库。成功后显示“已创建任务”及跳转任务链接，任务继续使用订阅来源。失败项保留在当前视图，批量处理返回逐条结果，不清空未成功的选择。

“不下载”不创建占位、受阻或待确认任务，也不先创建再删除。结果持久保存，之后的订阅检查不再重新询问或自动下载。同一条记录的并发处理与重复提交必须幂等；另一会话已处理时，返回最新结果。

已拒绝与策略跳过的历史记录可以通过明确的“重新考虑”操作恢复为待复核；仅修改全局配置不会恢复。处理记录的身份以数据源和影片 ID 为基础，任务创建另做番号去重，不能仅凭相似标题合并。用户在作品列表等入口主动下载后，也应同步关联同一影片的发行记录，避免继续显示待复核。

## 数据与接口约束

- 使用独立的发行记录查询和处理接口，不将待复核内容放进任务列表或任务处理台。
- 后端直接保存处理状态、原因、时间和任务关联，不能依赖前端缓存表达用户决定。查询提供分页、筛选及准确的待复核计数，并在成功提交后更新相关演员统计。
- 已拒绝和策略跳过的结果不能受当前每位演员 25 条展示保留逻辑影响；待复核记录也不能因展示截断而丢失。展示窗口、持久决策和轮询去重需要分别处理。
- 现有 `QUEUED`、`BLOCKED` 和带任务关联的记录分别映射到待复核、策略跳过及已有任务状态；任务创建失败需单独辨别。不能直接把全部 pending 记录当作待复核。
- 已经被旧保留逻辑删除的记录无法可靠恢复原决策；迁移不宣称恢复。只读取仍可确认的历史数据，不自动补建任务、不自动重新抓取并询问历史记录。
- 复核处理与轮询、同影片关联演员之间需要统一的并发控制；创建任务使用持久的幂等身份，创建成功但状态保存失败时重试应关联原任务。

## 实现说明

复核结果保存在独立 SQLite 表中，不受演员快照的 25 条展示保留逻辑影响，取消订阅也不删除。演员统计和最近发行信息按持久记录汇总。任务创建使用现有番号去重；保存结果失败后再次处理会关联已创建的任务。

复核处理、迁移、订阅写入及任务关联在同一服务内串行校验；批量操作最多 100 部，返回逐条成功、未变更和失败结果。成功项移出选择，失败及未变更项保留。
